# 階段 8：驗證細節

進入本階段時才讀取本檔。SKILL.md 僅保留摘要；此處為完整分流與備援步驟。

## 前置

1. **向使用者索取驗證參數**（不可臆造）。
2. 以階段 5 已確認的 **Base URL** 判斷環境（不可略過）。

| Base URL 類型 | 判定 |
|---------------|------|
| 本地 | `localhost` / `127.0.0.1` / `::1`（含任意 port） |
| 非本地 | 其餘主機（測試／正式遠端） |

**禁止**一看到「驗證／開啟站台」就直接發佈或啟動本地站台。

---

## 執行順序

```
1. 取得驗證參數（向使用者索取，不可臆造）
        ↓
2. 確認 Base URL 類型（本地 / 非本地）
        ↓
3a. 非本地 ──→ 直接以該 Base URL 跑 MCP 呼叫 API
        │         ├─ 成功 → 驗證結束
        │         └─ 失敗 → 進入 3b（改走本地備援）
        ↓
3b. 本地，或非本地 MCP 失敗
        → 才可發佈／啟動本地站台
        → 將測試用 Base URL 改為本地
        → 再以 MCP 對本地站台驗證
```

### 非本地（3a）

- 使用階段 5／MCP 設定中的遠端 Base URL（注意 http／https 何者實際可連）。
- 透過 MCP（或其 `apiClient`）呼叫目標 API。
- 依使用者定義的成功條件判定（例如業務 `action_result`／特定 `action_message`），**勿**僅看 HTTP 連得上。
- 成功 → 結束；失敗 → 進入本地備援，並保留遠端錯誤訊息供回報。

### 本地／本地備援（3b）

僅在下列情況啟動本地站台：

- Base URL **本就是本地**；或
- **非本地 MCP 驗證已失敗**

步驟：

1. 依專案既有 skill／腳本發佈（若尚未含本次 API）並啟動本地站台。
2. **確認本地 Base URL（含 port、http／https）**——**不可假設固定 5000／5001**。依專案設定判定，優先順序：
   - 啟動腳本／skill 實際使用的 URL 或 port 參數（例如 `start-dev-server`）
   - `Properties/launchSettings.json` 的 `applicationUrl`／`ASPNETCORE_URLS`
   - 執行環境變數 `ASPNETCORE_URLS`
   - 啟動後實際 listening 的位址（若 HTTP 會轉向 HTTPS，以轉向後**可呼叫 API** 的 URL 為準）
3. **明確改用上述本地 Base URL** 再跑 MCP（勿對遠端重試卻只開本地；MCP 環境變數須同步）。
4. 本地 MCP 亦失敗時：回報**遠端錯誤**與**本地錯誤**，再請示使用者下一步。

---

## 本地備援注意

- 改測本地時，MCP／環境變數的 Base URL 必須同步改為**已確認的本地 URL**（含正確 port 與協定）。
- 本地 port／協定以專案設定為準，**勿寫死** 5000、5001 或其他慣例 port。
- WSL 呼叫 Windows 本機站台時，可能需走 Windows 端 HTTP 客戶端（例如 PowerShell）；本機自簽憑證需能完成 TLS（信任或略過驗證）。
- IP 白名單、DB 連線等基礎設施錯誤，與業務驗證失敗分開記錄。

---

## 完成判定

- 以使用者宣告的成功條件為準（參數正確、連線到達業務邏輯、預期回應）。
- 遠端成功即可結束，無需再開本地。
- 僅本地成功時，應註明「遠端未過、本地備援通過」及遠端失敗原因。
